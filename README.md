# Осмотр инфраструктуры МГТС

Локальный сайт для бригады МГТС находит распределительные щиты (РЩ) и телекоммуникационные климатические шкафы (ТКШ) на фото и в видео. Для каждого обнаружения можно открыть исходный кадр, увидеть рамку, прогноз состояния, решение и рекомендацию. Фильтр «Требуют проверки» включает кандидатов на ремонт. Кнопка «Скачать CSV» сохраняет строки с учётом фильтра.

## Запуск на MacBook M1

На этом Mac из папки проекта достаточно выполнить:

```bash
cd /Users/zeyd/Desktop/hak
python3 app.py
```

Откройте [сайт на Mac](http://127.0.0.1:8000). При переносе на другой Mac нужны Python 3.11+, инструменты командной строки Xcode и пакеты из `requirements.txt`. Готовая модель в `data/detector.npz` использует Apple Vision Feature Print revision 2 (macOS 14 и новее). Приложение собирает два нативных модуля при первом запуске. Изображения обрабатываются на этом Mac.

```bash
python3 -m venv .venv
.venv/bin/python3 -m pip install -r requirements.txt
.venv/bin/python3 app.py
```

Для демонстрации на втором устройстве запустите отдельный экземпляр:

```bash
python3 app.py --lan --port 8002
```

На телефоне или другом ноутбуке в той же сети Wi-Fi откройте адрес, который программа выведет в Терминале. В обычном режиме сайт доступен только на самом Mac.

Он строится из хеша исходного файла и номера обнаружения. Место в реестре МГТС по этому идентификатору установить нельзя.

«Фото.1.jpg» содержит подписи обоих типов на одной опоре. Это иллюстрация без эталонной оценки состояния, использованная только для демонстрации. В исходных папках отсутствуют видео, дорожные GPS-треки и таблица координат рамок. Для прототипа вручную добавлены 94 прямоугольные области в `data/regions.csv`. У 61 основной области тип и состояние берутся из соответствующей книги Excel. У 33 дополнительных областей размечен только тип объекта.

После проверки похожих ракурсов сформированы 46 обучающих фото (40 групп площадок) и 15 тестовых (12 групп). Исходные 13 тестовых снимков остались в тесте. Снимки `35453686.jpg` и `20184015.jpg` перенесены к вероятным ракурсам тех же площадок. Группы выделены по видимому оборудованию и обстановке. Инвентарных номеров площадок в исходных таблицах нет.

## Проверка и показ

1. Нажмите «Проверить на тестовой выборке». Сайт прогонит через обычную модель все 15 фото. Разверните «Сверить прогнозы с исходной разметкой» и выберите фотографию. Пунктир обозначает эталонную рамку. Для теста нужен доступ к исходным папкам на компьютере с сервером.
2. Для примера повреждения откройте `35453688.jpg`. У щита деформирован корпус. В отчёте предусмотрена проверка корпуса и креплений. Для разбора ошибки откройте `20190131.jpg`. В исходной таблице указана глубокая коррозия РЩ. Основная область щита пропущена детектором.
3. Выберите «Требуют проверки» и скачайте CSV. При неуверенном прогнозе появляется рекомендация ручного осмотра. Для уверенно распознанного механического повреждения выдаётся решение «Кандидат на ремонт».
4. Загрузите `data/demo-from-test-photos.mp4`. Это семисекундный технический пример из отложенных `10000639.jpg` и `20201019.jpg` с однотонным промежуточным кадром. В карточке есть границы интервала и переход к выбранному моменту ролика. Настоящая видеозапись поездки нужна для проверки качества на дороге.

Повторить численную проверку:

```bash
python3 app.py --test
```

В `data/test_report.csv` у каждого основного объекта есть исходная разметка, результат, пересечение рамок (IoU) и факт направления на проверку. При IoU от 0,5 основной объект считается найденным. Проверка типа и состояния включает пропуски в знаменатель.

| На 15 отложенных фото | Результат |
|---|---:|
| Найден основной объект | 12 из 15 |
| Найден основной объект и верно определён тип | 11 из 15 |
| Найден основной объект и верно определено состояние | 7 из 15 |
| Повреждённый основной объект найден и направлен на осмотр | 7 из 10 |
| Совпадения среди всех 23 выданных рамок с 22 ручными рамками | 15 из 23 |

Рамки для оценки нанесены при разработке прототипа. Таблицы МГТС дают оценку состояния основного оборудования на снимке. Числа относятся к указанному набору, включая промахи и лишние обнаружения.

## Как устроено распознавание

1. На изображении многошкальный поиск по градиентам и цвету предлагает области-кандидаты. Для обучения используются ручные рамки и участки фона из обучающей части.
2. Apple Vision извлекает признаки пикселей внутри предложенной области. Модели на этих признаках отличают объект от фона, уточняют рамку, оценивают тип и состояние. Пороги для фона и ручной проверки выбираются по обучающим площадкам. Имена файлов и тексты Excel используются для подготовки примеров и оценки после предсказания.
3. Для MP4/MOV AVFoundation извлекает примерно один кадр в секунду, увеличивая интервал у длинных видео. Лимит — 30 кадров. Похожие обнаружения на соседних кадрах связываются по пересечению рамок и визуальным признакам. Отчёт сохраняет интервал и кадр с наиболее приоритетной рекомендацией. Быстрый проезд, пропуск кадра и смена ракурса могут разбить один объект на несколько наблюдений.
4. Перед поиском оборудования программа проверяет декодирование и видимость деталей. Ошибки чтения, почти чёрные, белые, однотонные и сильно зашумлённые кадры попадают в журнал и CSV с причиной. Для видео указывается время выбранного кадра. Проверяются до 30 выбранных кадров ролика. Повреждение видеоконтейнера даёт отдельную запись без времени.

Для воспроизведения разбиения и обучения используйте папку, в которой лежат «Датасет-ДСС» и «Датасет-ДСС 2»:

```bash
python3 app.py --train --datasets ~/Downloads
python3 app.py --test
```

Для восстановления только таблиц выполните `python3 prepare.py --datasets ~/Downloads`. Входные книги и фотографии используются в режиме чтения.
